# Plan chi tiết P2.6: CLI `dm p2`, báo cáo cấu trúc, tái lập, gate P2

> Trạng thái: `Draft`, chờ duyệt · Thuộc: [Plan P2](plan.md)

## 1. Mục tiêu

Ghép P2.1–P2.4 thành một lệnh chạy được, có manifest, tái lập được. Thêm báo cáo cấu trúc để **người đọc kiểm tra cây trong vài phút**. Đóng phase bằng gate report đối chiếu G1–G9.

## 2. Lệnh

| Lệnh | Tác dụng |
|---|---|
| `dm p2 run` | Đọc `blocks.jsonl` → mục lục → cấp tiêu đề → dựng cây → loại mục → `nodes.jsonl`, `tree.json`, `tree.md`. Manifest phase `p2_tree` (file vào/ra, prompt nếu có dùng LLM, số đếm, chi phí) |
| `dm p2 eval [--truth]` | G1–G7 so với đáp án → `eval.json`; exit 1 nếu chưa đạt |
| `dm p2 report` | `tree_report.md` |
| `dm p2 sections export` / `import <csv>` | Vòng duyệt loại mục (P2.4) |
| `dm p2 golden [--check]` | Sinh hoặc kiểm tra `eval/golden_qa_v1.jsonl` (P2.5) |

| ℹ | Đái tháo đường › 7. Theo dõi sau điều trị | loại mục do LLM đề xuất | Duyệt bằng `dm p2 sections export` |

## 3. Báo cáo `tree_report.md`

1. **Tổng quan:**
   - số chương, bệnh, mục, mục con;
   - bệnh / chương: số trang, số block, số từ;
   - nguồn của cấp tiêu đề (quy tắc / mục lục / LLM);
   - nguồn của loại mục (từ điển / gần / kế thừa / LLM).
2. **Đối chiếu mục lục:**
   - bảng mục lục ↔ nút trong cây (✓ hoặc ✗), trang in khớp hay không;
   - bệnh có trong cây nhưng không có trong mục lục;
   - bệnh có trong mục lục nhưng không có trong cây.
3. **Ma trận bệnh × loại mục:** bệnh nào thiếu mục chuẩn nào (ví dụ chỉ 1/3 bệnh có `complication`). Giúp P4 biết dữ liệu nào có thể trống.
4. **Cảnh báo cần người xem:** nút rỗng, mục rất dài hoặc rất ngắn (so trung vị), `numbering_gap`, `missing_from_toc`, `orphan_subsection`, loại mục từ LLM hoặc khớp gần.
5. **Cây** (`tree.md` nhúng vào).

## 4. Tái lập (G8)

- `nodes.jsonl` chỉ phụ thuộc `blocks.jsonl`, mục lục và cấu hình → chạy lại cho **giống hệt từng byte**.
- Nếu có dùng LLM (sách thật): cache → $0 khi chạy lại.
