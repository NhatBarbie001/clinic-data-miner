# Plan chi tiết P1.6: CLI `dm p1`, đánh giá, báo cáo, gate P1

> Trạng thái: `Hoàn thành` (2026-10-21) · Báo cáo: [P1.6_report.md](P1.6_report.md) · Gate: [gate_report.md](gate_report.md) · Thuộc: [Plan P1](plan.md)

## 1. Mục tiêu

Ghép P1.1–P1.5 thành **một lệnh chạy được, chạy tiếp được, tái lập được**, có manifest (N8). Đánh giá tự động với đáp án, báo cáo trước/sau dễ đọc. Đóng phase bằng **gate report** đối chiếu G1–G12.

## 2. Lệnh

| Lệnh | Tác dụng |
|---|---|
| `dm p1 run [--scope pilot\|all] [--pages a-b] [--no-llm] [--force]` | Đọc → bỏ header/footer → dựng block → sửa OCR → áp quyết định duyệt → `blocks.jsonl`. Mặc định `--scope pilot`. `--force` bỏ qua tiến độ cũ (cache LLM vẫn dùng) |
| `dm p1 review export` / `dm p1 review import <csv>` | Hàng đợi duyệt (P1.5) |
| `dm p1 eval [--truth path]` | So với đáp án → `eval.json` + bảng chỉ tiêu G1–G9 (✓/✗); exit 1 nếu chưa đạt |
| `dm p1 report` | `report.md`: thống kê, từng trang trước/sau, các mục chờ duyệt |

**Manifest (`RunRecorder`, phase `p1_clean`):**
- File vào: PDF, quyết định duyệt.
- File ra: `lines`, `furniture`, `blocks_rules`, `blocks`.
- Prompt `p1_fix_ocr@v1`.
- Số lượng: dòng, block theo loại, sửa đổi chấp nhận / từ chối, mục duyệt.
- Chi phí LLM của lần chạy.

## 3. Báo cáo `report.md`

1. **Tổng quan:** số trang, block theo loại, số sửa đổi (chấp nhận / từ chối theo luật), số mục chờ duyệt, chi phí.
2. **Chỉ tiêu** (nếu có đáp án): bảng G1–G9.
3. **Theo trang:** text sau quy tắc ↔ text cuối, phần thay đổi được tô đậm.
4. **Mục chờ duyệt** (nếu còn).

## 4. Tái lập (G10)

- Chạy `dm p1 run` hai lần liên tiếp. Lần 2 dùng tiến độ và cache, tốn **$0**, và `blocks.jsonl` **giống hệt từng byte** (so sha256 trong manifest).
- `DM__LLM__MODE=replay dm p1 run --force` chạy được, không gọi API, ra cùng kết quả.
