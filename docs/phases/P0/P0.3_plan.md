# Plan chi tiết P0.3: LLM client (`core/llm_client.py`, `core/cache.py`, `core/budget.py`)

> Trạng thái: `Hoàn thành` (2026-10-20). Báo cáo: [P0.3_report.md](P0.3_report.md)
> Thuộc: [Plan P0](plan.md) · Nguyên tắc liên quan: N4 (idempotent, chạy tiếp được), N5 (mọi lời gọi LLM đi qua một cửa), N8 (manifest/chi phí)

## 1. Mục tiêu

Một **cửa duy nhất** để mọi module gọi LLM qua OpenRouter. Cửa này phải:
- **Tiết kiệm:** cùng một request thì không trả tiền hai lần (cache); vượt ngân sách thì dừng.
- **Bền:** tự retry khi lỗi tạm thời; lỗi vĩnh viễn thì báo rõ nguyên nhân (sai key, hết credit, sai model).
- **Đáng tin:** `chat_json` trả về object **đã validate** theo schema Pydantic, nếu không thì báo lỗi.
- **Test được miễn phí:** test không cần mạng, còn chế độ `replay` chạy lại pipeline từ cache.
- **Quan sát được:** mỗi lời gọi được ghi log gồm tác vụ, model, token, chi phí, thời gian, cache hit.

## 4. Thiết kế

### 4.1. Thành phần

```
core/
├─ llm_client.py   LLMClient: chat(), chat_json(), các hàm sync tương ứng; retry, fallback, semaphore
├─ cache.py        LLMCache (SQLite): get/put theo key; thống kê
├─ budget.py       CostLedger: nhật ký chi phí (JSONL), tổng đã chi theo tác vụ; kiểm tra ngân sách
└─ llm_types.py    LLMResponse, Usage, các lỗi: LLMError, CacheMissError, BudgetExceededError, LLMJSONError
```

**Thư viện mới:** `httpx`, để gọi HTTP bất đồng bộ và **mock bằng `httpx.MockTransport` trong test**. Mình chọn `httpx` thay cho OpenAI SDK vì kiểm soát hoàn toàn retry, header và body (`reasoning`, `usage`, `provider`), và mock dễ hơn.

### 4.2. Luồng một lời gọi

```
chat(task, messages, **override)
  │ spec = settings.model_for(task)   (+ override: temperature, max_tokens, reasoning, variant)
  │ payload = {model, messages, temperature, max_tokens, reasoning?, response_format?, usage:{include:true}}
  │ key = sha256(payload chuẩn hóa + variant)
  ├─ mode=live|replay: cache.get(key) → có thì trả về (cached=True, cost=0)
  ├─ mode=replay & không có → CacheMissError
  ├─ ledger.check(task)   → BudgetExceededError nếu đã chi ≥ ngân sách tác vụ hoặc tổng
  ├─ async with semaphore:
  │    for model in [spec.model, *spec.fallbacks]:
  │       retry tối đa max_retries: POST /chat/completions
  │         - 200 + choices hợp lệ          → thành công
  │         - 429/408/5xx/timeout/mất kết nối,
  │           hoặc 200 nhưng body có `error` / choices rỗng → chờ (backoff + jitter, ưu tiên Retry-After) rồi thử lại
  │         - 400/401/402/403/404           → LLMError ngay, không retry; 402 = "hết credit"
  │       hết lượt retry → thử model dự phòng kế tiếp
  ├─ ledger.add(task, model, usage, cost)   ← chi phí từ usage.cost; thiếu thì tự tính từ bảng giá
  ├─ cache.put(key, response)   (mode live|refresh)
  └─ trả về LLMResponse
```

**Khóa cache** gồm: model chính, messages, temperature, max_tokens, reasoning, response_format và `variant`.
- **Không** gồm: tên tác vụ, api key, timeout. Đổi những thứ này không cần gọi lại.
- **`variant`:** dùng khi cần nhiều output khác nhau cho **cùng một prompt** (P7 sinh dữ liệu với temperature > 0). `variant=0,1,2...` cho ra các mục cache khác nhau.

### 4.3. `LLMResponse`

```python
class LLMResponse(BaseModel):
    content: str                       # văn bản trả lời
    reasoning: str | None              # phần suy luận (nếu bật reasoning)
    reasoning_details: list | None     # giữ nguyên để gửi lại ở lượt sau (hội thoại nhiều lượt)
    model: str                         # model thực sự trả lời (có thể là model dự phòng)
    provider: str | None
    finish_reason: str | None          # "stop" | "length" | ...
    usage: Usage                       # prompt/completion/reasoning tokens, cost_usd
    cached: bool
    latency_s: float
    attempts: int                      # số lần gọi HTTP đã dùng
    cache_key: str
```

- `finish_reason == "length"` (output bị cắt ngang) **được ghi log cảnh báo**.
- Với `chat_json`, output bị cắt là lỗi, vì JSON sẽ không hoàn chỉnh.

### 4.4. `chat_json(task, messages, schema)`

1. Gửi `response_format = {"type": "json_schema", "json_schema": {"name", "schema": schema.model_json_schema()}}`.
2. Parse nội dung: bỏ rào ```` ```json ```` nếu có, `json.loads`, rồi `schema.model_validate`.
3. Sai thì thêm vào hội thoại: lượt assistant (output sai) + lượt user ("JSON không hợp lệ: <lỗi>. Trả lại đúng schema."), rồi gọi lại. Tối đa `json_retries` lần (mặc định 2).
4. Vẫn sai thì báo `LLMJSONError` kèm output cuối và danh sách lỗi.
5. Kết quả: `(parsed_object, LLMResponse)`.

**Một kết quả cache sai schema sẽ không bị dùng lại mãi.** Nếu output lấy từ cache mà không hợp lệ, lượt sửa lỗi đi qua key khác (hội thoại dài hơn), nên không bị kẹt trong vòng lặp.

### 4.5. Ngân sách và nhật ký chi phí (`budget.py`)

- `data/cache/cost_log.jsonl`: mỗi lời gọi **thật** (không tính cache hit) ghi một dòng gồm `ts, task, model, prompt_tokens, completion_tokens, reasoning_tokens, cost_usd, latency_s, cache_key`.
- Tổng đã chi được tính lại từ log khi khởi động, nên **ngân sách được giữ qua nhiều lần chạy**.
- Trước mỗi lời gọi thật: tổng đã chi ≥ `budget.total_usd`, hoặc chi của tác vụ ≥ `budget.per_task_usd[task]`, thì báo `BudgetExceededError`.
- Đây là kiểm tra *trước khi gọi*. Một lời gọi có thể vượt ngưỡng một chút; với chi phí mỗi lời gọi rất nhỏ, mức vượt này chấp nhận được.
- Chi phí lấy từ `usage.cost` do OpenRouter trả về (đã tính đúng khung giờ). Nếu thiếu thì tính theo bảng giá cơ bản trong `data/cache/models.json` và đánh dấu `cost_estimated=true`.

### 4.6. Cache (`cache.py`)

- SQLite `data/cache/llm_cache.sqlite`, bảng `responses(key PRIMARY KEY, model, created_at, request_json, response_json)`.
- Ghi theo từng lời gọi và commit ngay, nên khi tiến trình bị ngắt thì phần đã xong vẫn còn (N4).
- Có `stats()` (số mục, dung lượng) cho `dm llm cost`.

### 4.7. CLI

| Lệnh | Tác dụng |
|---|---|
| `dm llm models` | Tải `GET /models` → lưu `data/cache/models.json`; với **mỗi tác vụ** trong `models.yaml`: model có tồn tại không, giá, có hỗ trợ `response_format` / `reasoning` không. Exit 1 nếu có model không tồn tại. |
| `dm llm ping` | (1) 1 câu hỏi tiếng Việt bằng `chat`; (2) 1 lời gọi `chat_json` với schema nhỏ. In kết quả, token, chi phí, cache hit. Chạy lần 2 phải là cache hit, chi phí $0. |
| `dm llm cost` | Tổng chi theo tác vụ/model, ngân sách còn lại, thống kê cache |
