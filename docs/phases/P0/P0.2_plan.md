# Plan chi tiết P0.2: Cấu hình (`core/config.py`, `configs/*.yaml`)

> Trạng thái: `Draft`, chờ duyệt
> Ngày tạo: 2026-10-19
> Thuộc: [Plan P0](plan.md) · Nguyên tắc liên quan: N7 (cấu hình tách khỏi code), N8 (manifest có hash cấu hình), N5 (model theo tác vụ)

## 1. Mục tiêu

Có **một nguồn cấu hình duy nhất, được kiểm tra kiểu** cho toàn bộ dự án. Mọi module sau này lấy đường dẫn, model, ngân sách và tham số từ `Settings`, không hard-code.

Câu hỏi mà task này phải trả lời được:
- Model nào được dùng cho tác vụ X? → `settings.model_for("extract")`
- Dữ liệu của phase P1 nằm ở đâu? → `settings.paths.data_dir / "p1_clean"`
- Đang chạy chế độ LLM nào, giới hạn đồng thời bao nhiêu, ngân sách còn bao nhiêu?
- Lần chạy này dùng cấu hình nào? → `settings.fingerprint()` (hash, ghi vào manifest)

## 2. Phạm vi

- **Làm:** schema `Settings`, bộ nạp cấu hình nhiều lớp, che bí mật, hash cấu hình, lệnh CLI `dm config show|validate`.
- **Không làm:** gọi API OpenRouter (P0.3). Kiểm tra model ID có tồn tại trên OpenRouter cũng để P0.3, vì cần API.

## 3. Thiết kế

### 3.1. Các lớp cấu hình (lớp sau ghi đè lớp trước)

```
1. configs/default.yaml     ← commit, giá trị mặc định cho mọi người
2. configs/models.yaml      ← commit, ánh xạ tác vụ → model (nạp vào khóa `models`)
3. configs/local.yaml       ← KHÔNG commit, tùy chỉnh trên máy cá nhân (tùy chọn)
4. Biến môi trường / .env   ← bí mật + ghi đè nhanh khi chạy
```

- **Gộp sâu (deep merge):** `local.yaml` chỉ cần ghi khóa muốn đổi, ví dụ `llm: {concurrency: 2}`, các khóa khác giữ nguyên.
- **Biến môi trường** dùng tiền tố `DM__` và `__` để phân cấp, ví dụ `DM__LLM__MODE=replay`, `DM__LLM__CONCURRENCY=8`. Giá trị được parse như YAML, nên `8` → int, `true` → bool.
- **Ngoại lệ:** API key đọc từ `OPENROUTER_API_KEY` (tên chuẩn của OpenRouter, không cần tiền tố).

### 3.2. Schema `Settings` (Pydantic, `extra="forbid"`: gõ sai tên khóa sẽ báo lỗi ngay)

```yaml
project:
  book_id: "book01"            # dùng trong ID ổn định và tên artifact
  book_file: "book01.pdf"      # file trong data/raw/

paths:                         # tương đối với gốc repo → được resolve thành đường dẫn tuyệt đối
  raw_dir: data/raw
  data_dir: data
  cache_dir: data/cache
  samples_dir: samples
  prompts_dir: prompts
  eval_dir: eval

llm:
  base_url: https://openrouter.ai/api/v1
  mode: live                   # live | replay | refresh
  concurrency: 4               # 1..64
  max_retries: 4               # 0..10
  timeout_s: 120
  api_key: <từ OPENROUTER_API_KEY, kiểu SecretStr, không bao giờ in ra>

budget:                        # USD, dừng khi vượt (thực thi ở P0.3)
  total_usd: 20.0
  per_task_usd: {}             # vd. {extract: 5.0}; không có thì chỉ áp total

models:                        # nạp từ configs/models.yaml
  <task>:
    model: "<openrouter model id>"
    temperature: 0.0
    max_tokens: 4096
    fallbacks: []              # model dự phòng khi model chính lỗi hoặc hết quota

pilot:                         # chương mẫu (điền ở P0.6)
  page_start: null
  page_end: null
  diseases: []
```

**Ràng buộc kiểm tra:**
- `concurrency` từ 1 đến 64; `max_retries` từ 0 đến 10.
- `budget` ≥ 0.
- `pilot.page_start ≤ page_end`, cả hai cùng có hoặc cùng trống.
- `models` phải có đủ **các tác vụ bắt buộc**: `ping, fix_ocr, classify, extract, qa, judge, datagen`.
- `temperature` từ 0 đến 2.

### 3.3. API công khai

```python
from dataminer.core.config import get_settings, load_settings

s = get_settings()                    # nạp 1 lần, dùng lại (cache)
s.model_for("extract")                # → ModelSpec; tác vụ không tồn tại → lỗi liệt kê các tác vụ hợp lệ
s.require_api_key()                   # → str; thiếu key → lỗi hướng dẫn tạo .env
s.fingerprint()                       # → sha256 ngắn của cấu hình (đã bỏ bí mật), dùng cho manifest
s.to_display_dict()                   # → dict đã che bí mật, dùng cho `dm config show`

load_settings(root=..., env={...})    # cho test: chỉ định gốc và môi trường, không đọc môi trường thật
```

### 3.4. Thông báo lỗi phải chỉ rõ nguồn

Ví dụ:
```
Cấu hình không hợp lệ (3 lỗi):
  - llm.concurrency: phải ≤ 64 (nhận 100)  [nguồn: configs/local.yaml]
  - llm.concurency: khóa không tồn tại – có phải ý bạn là 'concurrency'?
  - models: thiếu tác vụ bắt buộc: judge
```
Mỗi lỗi chỉ ra khóa đầy đủ, lý do, file gây ra lỗi, và gợi ý tên đúng khi gõ nhầm (dùng `difflib`).

### 3.5. CLI

| Lệnh | Tác dụng |
|---|---|
| `dm config show` | In cấu hình cuối cùng (YAML, đã che key), kèm nguồn của từng lớp và fingerprint |
| `dm config validate` | Exit 0 nếu hợp lệ; exit 1 kèm danh sách lỗi nếu không |

## 5. Model mặc định đề xuất (`configs/models.yaml`)

| Tác vụ | Dùng ở | Yêu cầu | Hạng model đề xuất |
|---|---|---|---|
| `ping` | P0.3 | Rẻ nhất | Nhỏ, rẻ |
| `fix_ocr` | P1 | Tiếng Việt tốt, rẻ, nhiều lời gọi | Nhỏ hoặc trung bình, rẻ |
| `classify` | P2, P4 | Phân loại ngắn | Nhỏ, rẻ |
| `extract` | P4 | Chính xác, JSON tốt, context dài | Mạnh |
| `qa` | P5 | Tool calling tốt, tiếng Việt tốt | Mạnh |
| `judge` | P5, P7 | **Khác họ model** với `qa`/`datagen` để tránh tự chấm điểm mình | Mạnh, khác nhà cung cấp |
| `datagen` | P7 | Viết đa dạng, tiếng Việt tự nhiên | Mạnh hoặc trung bình |

**Model ID cụ thể sẽ được kiểm tra ở P0.3** bằng lệnh `dm llm models`, gọi `GET /models` của OpenRouter để xác nhận model tồn tại và lấy giá. Ở P0.2, mình điền ID theo đề xuất hoặc theo lựa chọn của bạn.
