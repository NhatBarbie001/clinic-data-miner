> Trạng thái: `Hoàn thành`

## 1. Đã làm gì

- **`BaseRecord`:** lớp cha của mọi bản ghi. Tự điền `schema_version`; đọc file do code phiên bản khác tạo ra thì báo lỗi kèm hướng dẫn; khóa lạ bị từ chối.
- **`stable_id()`:** ID ổn định theo nội dung, đã chuẩn hóa Unicode, nên chữ Việt dựng sẵn và tổ hợp cho cùng ID.
- **I/O an toàn:**
  - Ghi JSONL/JSON **atomic**, không bao giờ để lại file hỏng.
  - Đọc từng dòng có validate; lỗi báo `file:dòng: trường: lý do` **bằng tiếng Việt**.
  - Append từng bản ghi và **chạy tiếp sau khi bị ngắt**, tự dọn dòng ghi dở.
- **`RunRecorder`:** mỗi lần chạy phase có manifest (git commit, fingerprint cấu hình, model, prompt, file vào/ra kèm sha256 và số bản ghi, chi phí LLM phát sinh, trạng thái) và **file log riêng**.
- **Logging thống nhất** (console + file); `dm --log-level`.
- **CLI:** `dm runs list`, `dm runs show <phase|run_id>`.
- **Script minh họa** `scripts/demo_io.py`: chạy dở rồi chạy tiếp.
- **Refactor:** phần dịch lỗi Pydantic sang tiếng Việt được tách thành `core/errors_vi.py`, dùng chung cho cấu hình (P0.2) và dữ liệu.

**Mẫu dùng ở các phase sau:**
```python
class Block(BaseRecord):            # schema nghiệp vụ của phase
    SCHEMA_VERSION: ClassVar[int] = 1
    page: int
    text: str

with RunRecorder(settings, phase="p1_clean") as run:
    done = read_done_ids(progress)                # chạy tiếp
    for item in todo:
        if item.id in done: continue
        append_jsonl(progress, process(item))     # ghi từng bản ghi
    n = write_jsonl(final, read_jsonl(progress, Block))   # bản cuối, atomic
    run.add_output(final); run.count("blocks", n)
```

## 7. Vấn đề và ghi chú

**Lỗi phát hiện khi xem output mẫu, đã sửa trước khi chốt:**
1. **Thông báo lỗi đọc dữ liệu bằng tiếng Anh** ("Field required", "Input should be...").
   - **Sửa:** tách `core/errors_vi.py`, dùng chung với cấu hình; thêm các kiểu lỗi số nguyên, danh sách rỗng...
   - Test `test_03` kiểm tra thông báo tiếng Việt.
2. **Hai lần chạy cùng mốc giây** nên `dm runs list` không sắp xếp đúng.
   - **Sửa:** `run_id` và `started_at` có mili-giây.
3. **`duration_s` lệch với `started_at`/`finished_at`** (0.007s so với 107ms), vì `started_at` lấy lúc khởi tạo, trước khi chạy các lệnh git (khoảng 100ms).
   - **Sửa:** `started_at` tính từ lúc vào khối `with`.
   - Thêm test `test_11b`; đã xác nhận test fail khi bỏ bản sửa.

**Quyết định đã đưa ra:**
- Io **không tự chuẩn hóa NFC** nội dung, chỉ đảm bảo ghi và đọc lại giống hệt. Chuẩn hóa văn bản là việc của P1. Riêng `stable_id` có chuẩn hóa để ID không phụ thuộc dạng Unicode.
- Chi phí LLM của lần chạy lấy bằng chênh lệch sổ chi phí (P0.3), dùng lại `CostLedger`, không sửa `LLMClient`.
- `manifest.json` ở thư mục phase luôn là lần chạy gần nhất; `runs/` giữ toàn bộ lịch sử.

**Hạn chế đã biết:**
- Lỗi "không phải JSON" vẫn giữ mô tả gốc tiếng Anh của Python (`Expecting property name...`). Đã có số dòng và số cột nên đủ để tìm lỗi.
- Nếu hai tiến trình cùng append vào một file, các dòng có thể xen nhau. Pipeline hiện chạy một tiến trình mỗi phase (song song bằng async bên trong), nên chưa cần khóa file.
