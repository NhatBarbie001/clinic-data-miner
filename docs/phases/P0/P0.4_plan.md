# Plan chi tiết P0.4: I/O, schema cơ sở, manifest, logging

> Trạng thái: `Hoàn thành` (2026-10-20). Báo cáo: [P0.4_report.md](P0.4_report.md)
> Thuộc: [Plan P0](plan.md) · Nguyên tắc liên quan: N1 (giao tiếp qua file), N2 (hợp đồng dữ liệu Pydantic), N3 (truy vết, ID ổn định), N4 (idempotent, chạy tiếp được), N8 (manifest)

## 1. Mục tiêu

Mọi phase từ P1 trở đi đọc và ghi dữ liệu theo **cùng một cách an toàn**:
- **Không bao giờ để lại file hỏng.** Ghi kiểu atomic: ghi ra file tạm rồi mới đổi tên. Nếu tiến trình chết giữa chừng thì file cũ còn nguyên.
- **Dữ liệu sai bị chặn ngay ở biên.** Mỗi dòng JSONL được validate bằng schema Pydantic; lỗi báo rõ `file:dòng` và tên trường sai.
- **Chạy tiếp được.** Các bước gọi LLM ghi từng bản ghi (append). Khi chạy lại thì bỏ qua các `id` đã xong; một dòng bị ghi dở do tiến trình chết được tự dọn.
- **Mỗi lần chạy có manifest** (N8): phase, thời gian, git commit, fingerprint cấu hình, model, prompt, file vào/ra (số bản ghi + sha256), chi phí LLM phát sinh, trạng thái thành công/thất bại.
- **Log thống nhất:** console + một file log riêng cho mỗi lần chạy.

## 2. Phạm vi

- **Làm:** `core/schemas.py`, `core/io.py`, `core/run.py`, `core/logging.py`, CLI `dm runs list|show`, script minh họa `scripts/demo_io.py`.
- **Không làm:**
  - Schema nghiệp vụ (Block, Node, Disease...): mỗi phase tự định nghĩa, kế thừa `BaseRecord`.
  - Quản lý prompt theo version: P1 sẽ tạo `prompts/` loader. Manifest đã có sẵn chỗ ghi prompt.

## 3. Thiết kế

### 3.1. `core/schemas.py`

```python
class BaseRecord(BaseModel):
    """Lớp cha của mọi bản ghi lưu ra file. Khóa lạ bị từ chối."""
    SCHEMA_VERSION: ClassVar[int] = 1      # lớp con tăng khi đổi schema
    id: str                                # ID ổn định (N3)
    schema_version: int                    # tự điền = SCHEMA_VERSION; đọc thấy khác thì báo lỗi rõ

def stable_id(*parts, prefix="") -> str
    # sha1 của các phần (đã chuẩn hóa Unicode NFC, nối bằng \x1f) → 16 ký tự hex, vd. "blk_3fa9c0d12e7b4a55"
    # Cùng nội dung → cùng ID, dù chạy lại bao nhiêu lần. "ế" dựng sẵn và "ế" tổ hợp → cùng ID.

class RunManifest(BaseModel):
    run_id, phase, status: running|success|failed,
    started_at, finished_at, duration_s,
    git_commit, git_dirty, config_fingerprint,
    models: {task: model}, prompts: {prompt_id: version},
    inputs: [FileInfo], outputs: [FileInfo]     # FileInfo = {path (tương đối gốc repo), records, sha256, bytes}
    llm: {calls, cost_usd}                      # phát sinh trong lần chạy (lấy chênh lệch sổ chi phí)
    counts: {tên: số}, notes: [str], error: str | None
```

**Nhất quán với P0.3:** chi phí LLM của lần chạy = tổng `cost_log.jsonl` sau trừ trước. Không cần sửa `LLMClient`.

### 3.2. `core/io.py`

| Hàm | Hành vi |
|---|---|
| `write_jsonl(path, records) -> int` | Ghi atomic (tmp cùng thư mục → `os.replace`); tự tạo thư mục; UTF-8, `ensure_ascii=False`; trả số bản ghi. Lỗi giữa chừng → xóa tmp, file cũ nguyên vẹn. |
| `read_jsonl(path, model) -> Iterator[T]` | Đọc từng dòng (không nạp cả file vào RAM), validate; bỏ dòng trống; lỗi → `DataFileError("<file>:<dòng>: <trường>: <lý do>")` |
| `append_jsonl(path, record)` | Thêm 1 dòng + flush. Dùng cho bước gọi LLM ghi từng kết quả. |
| `read_done_ids(path) -> set[str]` | Tập `id` đã ghi (đọc nhanh, không validate), **tự dọn dòng cuối bị ghi dở** |
| `repair_tail(path) -> bool` | Cắt dòng cuối nếu không kết thúc bằng `\n` và không phải JSON hợp lệ |
| `write_json` / `read_json` | JSON thường, ghi atomic (dùng cho manifest, cấu hình xuất ra) |
| `file_info(path, root)` | `FileInfo`: số dòng, sha256, dung lượng |

**Dữ liệu không bị sửa:** io **không** tự chuẩn hóa NFC nội dung. Việc chuẩn hóa thuộc P1 (`text_vi`). Io chỉ đảm bảo ghi và đọc lại **giống hệt từng byte**.

### 3.3. `core/run.py`: `RunRecorder`

```python
with RunRecorder(settings, phase="p1_clean") as run:     # thư mục: data/p1_clean/
    run.use_prompt("p1_fix_ocr", "v1")
    run.add_input(pdf_path)
    n = write_jsonl(out, records); run.add_output(out)
    run.count("blocks", n); run.note("bỏ 12 header/footer")
# → data/p1_clean/runs/<run_id>.json  (manifest)
#   data/p1_clean/runs/<run_id>.log   (log riêng lần chạy)
#   data/p1_clean/manifest.json        (bản sao của lần chạy GẦN NHẤT)
```

- Vào khối: ghi manifest `status=running`, gắn file log riêng cho lần chạy.
- Ra khối bình thường: `status=success`.
- Ra khối do exception: `status=failed`, ghi `error`, **exception vẫn được ném tiếp** (không nuốt lỗi).
- `run_id = <phase>_<YYYYmmdd-HHMMSS>_<4 hex>`: sắp xếp được theo thời gian và không trùng.
- Thông tin git: lấy `git rev-parse HEAD` và `git status --porcelain`. Không có git thì để `null`, không lỗi.

### 3.4. `core/logging.py`

- `setup_logging(level="INFO")`: một handler console (stderr), gọi nhiều lần không bị nhân đôi.
- `RunRecorder` thêm file handler UTF-8 trong thời gian chạy rồi gỡ ra khi xong.
- Định dạng: `2026-10-20 10:15:03 INFO dataminer.llm: ...`
- `dm` gọi `setup_logging` lúc khởi động, có tùy chọn `--log-level`.
