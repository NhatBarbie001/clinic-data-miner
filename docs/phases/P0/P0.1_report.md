## 5. Cách tự kiểm tra

```bash
cd Data-miner
uv sync                               # cài môi trường từ uv.lock
uv run dm info                        # mọi dòng phải là "ok", không có "THIẾU"/"LỖI"
uv run pytest -v                      # 38 passed
uv run ruff check . && uv run ruff format --check . && uv run mypy
uv run pre-commit run --all-files     # 9 hook Passed (cần git add trước vì pre-commit chỉ xét file đã track)
uv run dm info > out.txt              # chuyển hướng output → không lỗi, out.txt đọc được tiếng Việt
```

## 7. Vấn đề và ghi chú

**Lỗi đã phát hiện và sửa:**
- `dm info > file` trên Windows bị `UnicodeEncodeError`, vì Python dùng code page `cp1258` khi output bị chuyển hướng.
- Test bằng `CliRunner` không bắt được lỗi này.
- **Sửa:** entry point mới `main()` ép stdout/stderr sang UTF-8 trước khi chạy CLI.
- **Test hồi quy:** `test_cli_subprocess_redirected_output_is_utf8` chạy CLI như tiến trình thật. Đã xác nhận: gọi `app()` cũ thì exit=1, gọi `main()` mới thì exit=0.

**Quyết định đã đưa ra:**
- `samples/` **được loại khỏi** các hook tự sửa whitespace/EOF, vì đây là output nguyên văn và không được chỉnh sửa.
- `uv.lock` được loại khỏi giới hạn 200 KB, vì là file sinh tự động.
- `.gitattributes` chuẩn hóa xuống dòng về LF để tránh diff giả giữa Windows và Linux.
- Hook ruff và mypy dùng `language: system` qua `uv run`, để chạy đúng phiên bản trong `uv.lock`.
- mypy strict chỉ áp dụng cho `src/`; code test được ruff kiểm tra.

**Việc còn tồn đọng / cần chủ dự án quyết định:**
- **Commit:** các file đã `git add` nhưng **chưa commit**. Bạn muốn mình commit sau mỗi task, hay bạn tự commit?
- `pre-commit install` (tự chạy hook khi commit) chưa bật, sẽ bật khi bắt đầu commit.
- Chưa có `.env`. Cần trước P0.3.
- Chưa có PDF. Cần trước P0.5.
